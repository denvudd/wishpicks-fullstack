# Wish Item Filter (API + Frontend)

## Description

Implemented server-side filtering for wish items across both API and frontend. Four filter dimensions: reservation status, fulfillment status, priority (multi-select), and store domain. Added a filter panel in the wishlist detail page with a slideover, active filter chips, and a clear button.

## Session Log

### API — DB Migrations

1. `app/models/reservation.py` — added `is_fulfilled: Mapped[bool]` column (NOT NULL, default false). Migration autogenerated; `server_default=sa.false()` added manually.

2. `app/models/wish_item.py` — added `store_domain: Mapped[str | None]` column with index. Populated from `product_url` via `urllib.parse.urlparse` (strips `www.`). Two migrations: schema (`add_store_domain_to_wish_items`) + data backfill (`backfill_wish_items_store_domain`) using PostgreSQL regex.

### API — Service & Schema Changes

3. `app/services/items.py`:
   - `_extract_store_domain(url)` — parses hostname, strips `www.` prefix
   - `get_is_fulfilled(db, item_id)` — counts fulfilled reservations via correlated subquery
   - `list_items()` — extended with `is_reserved`, `is_fulfilled`, `priority`, `store` filter params; separate unfiltered `DISTINCT` query returns `available_stores`; returns `(rows, total, available_stores)`
   - `create_item()` / `update_item()` — now set `store_domain` from `product_url`
   - `build_item_response()` — added `is_fulfilled` parameter

4. `app/schemas/items.py` — added `is_fulfilled: bool` to `WishItemResponse`; added `available_stores: list[str]` to `WishItemListData`

5. `app/routers/wishlists.py` `list_items` — added query params: `is_reserved`, `is_fulfilled`, `priority: list[int] | None`, `store`; returns `available_stores` in response

6. `app/routers/items.py` — all three item endpoints (`get_item`, `update_item`, `update_position`) now fetch and return `is_fulfilled`

### Frontend

7. `types/api.ts` — added `is_fulfilled: boolean` to `WishItemResponse`; added exported `ItemFilters` interface

8. `stores/useItemStore.ts` — added `availableStores: string[]` state + `setAvailableStores()` action; `clear()` resets it

9. `composables/api/useItemsApi.ts` — `list()` accepts `filters?: Partial<ItemFilters>`, builds query params, returns `availableStores`; `ItemListData` extended with `available_stores`

10. `composables/useItems.ts` — `fetchList()` accepts filters, stores `availableStores`; exposes `availableStores` computed

11. `locales/uk.json` + `en.json` — added `items.filters.*` keys

12. `components/items/ItemFilterSlideover.vue` (new) — four sections (reservation, fulfillment, priority pills, store checkboxes); radio-like behavior for reservation/fulfillment; multi-select for priority; props: `open`, `modelValue: ItemFilters`, `availableStores`; emits `update:open`, `update:modelValue`

13. `pages/wishlists/[id]/index.vue`:
    - Filter state `filters` ref + `activeFilterCount` computed
    - Toolbar: grid toggle + filter button (with `UChip` badge count) + clear button (visible when filters active)
    - Active filter chips row: per-chip removal by clicking; colors differ by type (subtle/solid/outline)
    - `watch(filters, fetchList, { deep: true, immediate: true })` — replaces explicit `fetchList` call in `onMounted`
    - `ItemsItemFilterSlideover` wired with `v-model`

## Session Outcomes

- `is_fulfilled` derived from `Reservation.is_fulfilled` boolean — not stored on `WishItem`
- `store_domain` stored as a separate indexed column; backfilled via data migration
- `available_stores` always returned unfiltered so UI shows all options regardless of active filters
- Correlated subqueries reused as both SELECT labels and WHERE conditions
- All filter changes trigger an immediate server-side refetch via deep watch

## Lessons Learned

- `alembic revision --autogenerate` requires the DB to be fully up to date first (`upgrade head`)
- Autogenerate misses `server_default` for NOT NULL boolean columns — must be added manually
- Nuxt auto-import naming: `components/items/ItemFilterSlideover.vue` → `<ItemsItemFilterSlideover>` (not `ItemsItemsFilter...`)
- Windows: run Alembic via `docker exec wishpicks-api-1 alembic ...` instead of `uv run` due to `.venv/lib64` symlink issue
